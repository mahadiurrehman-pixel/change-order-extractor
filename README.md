# Change Order Extractor

A Python-based pipeline for extracting structured information from construction change-order PDFs using an LLM, with evidence-backed fields, schema validation, and human-review flags.

## Features

- Extract text from selectable-text PDFs using PyMuPDF.
- Extract change-order details through the Groq API.
- Validate structured output with Pydantic.
- Attach source evidence and model-estimated confidence to extracted fields.
- Represent missing information as `null`.
- Preserve conflicting candidates and their supporting evidence.
- Flag ambiguous documents for human review.
- Run automated tests without making live API calls.

## Extracted Fields

- `change_order_id`
- `project_name`
- `description`
- `change_reason`
- `cost_impact.amount`
- `cost_impact.currency`
- `schedule_impact_days`
- `approval_status`

Each field includes `value`, `evidence`, and `confidence`. The result also includes `review_required`, `review_reasons`, and `conflicts`.

## Architecture

1. **Document reader:** reads selectable text from PDFs.
2. **LLM extraction:** requests structured JSON from Groq.
3. **Schema validation:** validates field types, evidence, confidence bounds, and conflicts.
4. **Review handling:** preserves conflicting candidates instead of silently choosing a value.
5. **CLI:** outputs the validated result as JSON.

## Requirements

- Python 3.11 or later
- A Groq API key
- Dependencies listed in `requirements.txt`

## Setup

Clone the repository:

```bash
git clone https://github.com/mahadiurrehman-pixel/change-order-extractor.git
cd change-order-extractor
```

Create and activate a virtual environment:

```bash
python -m venv .venv
source .venv/bin/activate
```

Install dependencies:

```bash
python -m pip install -r requirements.txt
```

Create a `.env` file in the project root:

```env
GROQ_API_KEY=your_groq_api_key
GROQ_MODEL=llama-3.3-70b-versatile
```

Replace the placeholder with your own API key. Never commit `.env` or publish credentials.

## Usage

Extract a normal sample PDF:

```bash
PYTHONPATH=src python scripts/extract_pdf.py samples/change_order.pdf
```

Try the ambiguous sample:

```bash
PYTHONPATH=src python scripts/extract_pdf.py samples/ambiguous_change_order.pdf
```

The ambiguous sample contains competing cost and schedule values. The expected behavior is to preserve the candidates, set `review_required` to `true`, and avoid silently choosing a final value.

## Tests

Run automated tests:

```bash
PYTHONPATH=src python -m pytest -v
```

Run lint checks:

```bash
ruff check src tests scripts
```

The current test suite contains 16 tests. These tests validate document reading and schema behavior without requiring a live Groq API call.

## Design Decisions

- **Evidence-backed extraction:** extracted values require supporting evidence.
- **Conservative missing-data handling:** missing values remain `null`.
- **Explicit ambiguity:** conflicting candidates are preserved.
- **Human review:** detected conflicts require review and a reason.
- **Strict schema:** unexpected fields and invalid values are rejected.
- **Model confidence:** confidence scores are estimates, not calibrated probabilities.

## Limitations

- Scanned PDFs without selectable text require OCR, which is not implemented.
- Evidence quotes generated by the model must be checked against the source in critical workflows.
- Conflict detection depends on model behavior and is not guaranteed to catch every ambiguity.
- Confidence scores have not been calibrated against a labeled evaluation dataset.
- Real-world accuracy has not yet been established on a large representative dataset.
- A dedicated human-review interface is not included.

## Security

- Keep API credentials in local environment variables.
- Never commit `.env` or credentials.
- Treat document content as untrusted input.
- Validate model output before using it downstream.

## Evaluation Status

The normal and ambiguous sample PDFs have been manually tested with the live extraction pipeline. The local automated suite currently passes all 16 tests, and Ruff reports no lint issues.

These results demonstrate initial functionality, not production-level accuracy.
